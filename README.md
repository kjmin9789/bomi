# 보미 (Bomi)

하나만 해도 좋아요. 작은 행동을 기록하고 실천한 테마 수를 꽃으로 확인하는 로컬 웹앱입니다.

## 실행

로컬 버전은 Node.js 22 이상에서 실행합니다. Cloudflare 개발·검증에는 먼저 `npm ci`로 의존성을 설치합니다.

```sh
npm start
```

브라우저에서 http://127.0.0.1:4173 을 엽니다.

```sh
npm test
```

## 기능

- 이 컴퓨터의 Codex에 개인 프로젝트 작업 정리를 요청하고 초안 확인 후 기록
- 재테크·커리어·건강 행동 기록, 수정·삭제와 날짜별 탐색
- 하루에 실천한 서로 다른 테마 수에 따른 0~3단계 꽃과 월간 캘린더
- 작은 행동 제안, 완료 피드백, 미래 문장과 주간 회고
- 기록 보관함, JSON 백업·가져오기
- 실제 저장 데이터와 분리된 가상 예시 모드
- 앱이 열려 있는 동안 확인하는 알림

## 데이터와 공개 범위

이 저장소에는 앱 코드·테스트·UI 이미지와 일반적인 가상 예시만 포함됩니다. 실제 개인 기록, 미래 문장, 회고, 백업 파일, 기획 대화와 개인 문서는 포함하지 않습니다.

확인한 기록은 해당 브라우저의 localStorage에 저장됩니다. GitHub에 동기화하지 않습니다. Codex 정리 요청·연결 정보·근거를 포함한 결과 초안은 로컬 `.data/codex/`에 보관되며 공개 저장소와 정적 파일 제공 대상에서 제외됩니다. 브라우저 데이터를 삭제하면 기록이 사라질 수 있으므로 설정에서 백업하세요. 백업 파일을 저장소에 추가하지 마세요.

보미 로그인·기기 간 동기화·앱이 닫힌 상태의 푸시는 아직 지원하지 않습니다. 날짜 기준은 Asia/Seoul입니다.

## Codex로 한 일 가져오기

macOS에서 로그인된 Codex CLI와 로컬 보미 연결 프로그램을 실행합니다. **오늘/이날 한 일 가져오기**를 누르면 이 보미 폴더에서 새 정리 세션을 만들고 요청을 자동 전송합니다. 별도 전송 클릭이나 고정 채팅 ID는 필요 없습니다. Codex App Server의 읽기 전용 세션과 채팅 조회 도구를 사용하며, 최종 JSON을 연결 프로그램이 검증한 뒤 초안 파일에 저장합니다. 앱에서 세션 열기가 실패해도 수집은 계속됩니다.

정리 세션은 선택한 한국 날짜의 전체 개인 채팅과 아카이브에서 실제 완료 행동을 확인합니다. 정리 세션 하나만 요약하지 않습니다. 생성·갱신 날짜 대신 실제 턴 날짜를 확인하며 회사·범위 불명확한 작업, 계획, 실패, 자동 정리 자체는 제외합니다. 읽지 못한 범위와 불확실성은 결과에 표시합니다.

한 채팅의 여러 목적은 작업별로 나누고, 다른 채팅에 걸친 관련 작업은 공통 주제로 묶습니다. 같은 작업은 원본 채팅과 안정적인 작업 키로 다시 가져와도 갱신합니다. 내용·근거·테마를 사용자가 확인한 항목만 기록과 꽃에 반영합니다. 이전의 채팅당 한 항목 형식 초안도 읽을 수 있지만, 그 형식으로 이미 저장한 기록과 새 세부 항목은 자동 통합하지 않으므로 같은 날 재수집 시 중복을 확인하세요.

별도 AI API 키는 쓰지 않습니다. Codex의 로그인과 사용량을 사용합니다. 새 채팅을 연 것과 정리가 완료된 것을 구분하고, 검증된 로컬 결과 파일이 도착한 뒤 초안을 표시합니다. 열기 실패가 불명확하면 자동 재실행하지 않습니다. 요청 종료는 보미의 기다리기만 끝내며 Codex 작업을 중단하지 않습니다. `.data/`에는 개인 자료가 있으므로 공개하거나 Git에 추가하지 마세요.

## 개발

`app/`은 HTML/CSS/JavaScript, `server.mjs`는 허용된 정적 파일과 Codex 연결 API를 제공하는 로컬 서버, `codex-bridge.mjs`는 로컬 Codex 요청·초안 검증, `tests/`는 모델·연결·API 검증입니다. 색상은 CSS 토큰을 사용합니다. 글자는 최소 14px로 유지합니다.

주요(`.primary`)·보조(`.secondary`)·삭제(`.danger`) 버튼은 공통 크기 규격을 사용합니다. 최소 높이 48px·최소 너비 104px, 세로 14px/가로 21px 여백, 모서리 10px, 글자 14px/줄높이 20px/굵기 650입니다. 짧은 확인·취소 버튼은 같은 크기이며, 긴 문구는 내용에 맞게 늘어납니다. 보조 버튼은 회색 배경과 기본 글자색으로 중요도를 구분하며 크기를 줄이지 않습니다. 새 화면에서도 이 클래스를 재사용하고 별도 버튼 치수를 정의하지 않습니다.

변경은 작업 브랜치와 PR로 제안하고, 저장소 소유자가 검토한 뒤 Squash and merge 합니다.

## Cloudflare 버전

Workers·D1·Cloudflare Access를 사용하는 개인용 구성을 추가했습니다.
허용 이메일 한 개로 로그인하고 여러 기기에서 기록을 조회·저장할 수 있습니다.
서버 저장 전 로컬 복구 자료를 남기며, 서로 다른 기록·필드의 동시 수정은 자동 병합하며, 같은 필드를 다르게 수정하면 충돌로 알려 덮어쓰지 않습니다.

알림 시각과 기기 권한을 켜면 앱이 닫혀 있어도 웹 푸시를 보낼 수 있습니다.
이미 기록했거나 쉬어가는 날에는 보내지 않습니다.
실제 사용에는 Cloudflare 배포·Access 설정·알림 키 등록·기기별 수신 검증이 필요합니다.
`npm start`의 기존 로컬 버전은 별도로 유지됩니다.

설정, 무료 플랜 유지, 인증 검증 및 기존 기록 이관 방법은 [Cloudflare 배포 안내](cloud/README.md)를 참고하세요.
원격 버전의 Codex 자동 수집은 연결하지 않았으며, 로컬에서 확인한 기록을 JSON 백업으로 옮길 수 있습니다.


## 클라우드 화면에서 이 컴퓨터의 Codex 가져오기

각 컴퓨터에서 Node.js 22 이상과 Codex 앱을 준비하고, 이 버전의 보미 폴더에서 아래를 실행합니다. 주소는 본인의 보미 HTTPS 주소로 바꿉니다.

```sh
npm run bridge -- https://YOUR-BOMI.workers.dev
```

연결 프로그램은 `127.0.0.1:4174`에서 실행되므로 켜둔 터미널을 유지합니다. 클라우드 보미의 **오늘/이날 한 일 가져오기**를 누르면 새 Codex 세션에 자동으로 요청을 전송합니다. **설정 → 이 컴퓨터의 Codex 연결 설정**에서는 연결 프로그램의 실행 상태를 확인합니다. 최신 데스크톱 Chrome에서 로컬 연결 권한을 요청하면 허용합니다. 회사 정책이 차단한 연결은 우회하지 않습니다.

초안과 근거는 이 컴퓨터에서 읽고, 사용자가 확인한 기록만 기존 클라우드 기록에 추가·갱신합니다. 같은 계정의 다른 기기에서는 화면이 열린 동안 10초 간격과 앱 복귀 시 자동으로 반영됩니다. 열린 모달이나 작성 중인 폼은 입력 보호를 위해 갱신을 미룹니다. 전체 백업을 교체하지 않으며, 저장에 실패하면 수집 요청을 닫지 않고 브라우저의 전송 대기 자료와 로컬 초안을 보존합니다. 다른 기기의 별도 기록은 자동으로 합칩니다. 같은 기록의 같은 필드를 다르게 수정한 경우에는 입력을 보존하고 충돌을 알립니다.

연결은 실행할 때 지정한 HTTPS 원본 한 곳에만 허용합니다. 사이트 로그인 쿠키나 토큰을 로컬 프로그램으로 전송하지 않습니다. Codex가 사용하는 계정은 컴퓨터마다 달라도 되며, 보미의 저장 계정은 같습니다. 회사 자료 수집은 허용하지 않습니다. 휴대폰은 직접 입력·기록 조회·알림용이며 컴퓨터의 Codex를 원격 실행하지 않습니다.

완료된 초안은 가져오기를 사용한 브라우저의 알림에서 다시 열 수 있습니다. 테마가 없는 항목은 테마를 선택하거나 기록 체크를 해제한 뒤 **확인한 일 서버에 저장**을 누릅니다. 사용자 확인 전 초안을 자동으로 실제 기록으로 저장하지 않습니다. 연결 프로그램을 종료하면 진행 중 수집이 중단될 수 있으며, 다시 시작해도 요청을 자동 중복 실행하지 않습니다. App Server의 동적 도구는 실험 API이므로 Codex 업데이트 후 연결 검증이 필요합니다.

## 내 루틴 관리

오늘의 보미 바로 아래에서 반복 루틴과 한국시간 기준 알림 요일·시각을 확인하고 일정을 수정하거나 알림을 끌 수 있습니다. 루틴 이름·요일·시각과 기록할 테마를 설정하세요. 완료 답변은 같은 회차에 한 번만 행동 기록으로 저장하며 취침은 실제 누운 날짜·시각을 기록합니다. 테마를 미리 고르지 않았다면 첫 완료 답변에서 확인합니다. 알림 수신과 무응답은 완료로 간주하지 않습니다. 개인 일정은 공개 코드에 포함하지 않습니다.

로컬은 앱이 열려 있을 때, 클라우드는 등록된 기기에 5분 간격의 예약 확인으로 알림을 보냅니다. 운영체제·네트워크에 따라 수신이 늦거나 누락될 수 있습니다.

## 묶음 중심 기록 형식

저장 형식 v2는 `groups`에 묶음 ID·날짜·제목·테마를 저장하고, `records`에는 기록 ID·묶음 ID·본문 및 입력된 요약·결과만 저장합니다. 화면의 날짜·테마는 묶음에서 가져옵니다. 제목이 같아도 서로 다른 ID의 묶음은 자동 합쳐지지 않습니다.

v1 백업은 읽을 때 메모리에서 변환하며, 읽기만으로 서버 DB를 갱신하지 않습니다. 같은 날짜·묶음 이름·테마 조합을 묶고, 서로 다른 테마의 기존 기록은 별도 묶음으로 보존합니다. 다음 사용자 저장 시 v2로 저장하며 로컬 이전 값과 서버의 기존 백업 절차를 유지합니다. 구버전 앱에서는 v2를 읽을 수 없으므로 열린 화면을 새로고침해야 합니다.

Codex 정리 요청 v3는 `groups: [{groupKey, title, themes, items}]`를 반환합니다. 테마와 묶음 제목은 묶음에서 한 번 확인하고, 개별 작업에는 완료 내용과 원본 근거를 남깁니다. 원본 채팅과 안정적인 작업 키로 중복을 방지하며 이전 형식으로 진행 중이던 요청도 확인할 수 있습니다. 연결 프로그램 코드도 함께 업데이트한 뒤 다시 실행해야 새 요청 형식이 적용됩니다.
